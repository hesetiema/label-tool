# ⑦ 从学习到生产

这个工具是一个精简的教学实现。这一篇帮你理清：**它和工业级标注平台的差距在哪，以及沿着什么路径演进**。

---

## 1. 我们已经覆盖了什么

| 能力 | 状态 |
|---|---|
| 点云解析与渲染 | ✅ ascii/binary PCD、双视图 |
| 3D 框标注闭环 | ✅ 画框、拟合、编辑、属性 |
| 自动拟合算法 | ✅ PCA + 局部拟合（传统方法） |
| 格式互通 | ✅ 兼容 SUSTechPOINTS label JSON |
| 多传感器融合 | ✅ 3D 框投影到前视相机图、分屏对照 |
| 数据与算法分层 | ✅ core/viewer/交互解耦 |
| 撤销重做 | ✅ 命令模式 + 快照，连续操作合并（见 ⑧） |
| 多帧时序 | ✅ 跨帧 ID 一致 + 轨迹插值（见 ⑧） |
| 大规模性能 | ✅ 体素下采样 + 距离 LOD，100 万→27 万点（见 ⑧） |

这些恰好是"学会一个领域"最核心的部分：数据、算法、交互、渲染，外加面试高频的三块工程能力。

---

## 2. 与生产级工具的差距

回顾第一讲里提到的四层能力，我们主要覆盖了"理论 + 呈现"，而"系统与数据""质量与流程"这两层几乎是空白：

### 2.1 系统与数据层

| 缺失能力 | 为什么重要 |
|---|---|
| 分布式存储 | 真实数据集是 TB 级，单机存不下 |
| 任务调度与分发 | 几百个标注员并发工作，需要把任务切片、分派、回收 |
| 数据库与版本管理 | 标注会反复修改，需要历史版本、回滚、审计 |
| 权限与协作 | 不同角色（标注员/质检员/管理员）权限不同 |

### 2.2 质量与流程层

| 缺失能力 | 为什么重要 |
|---|---|
| 质检流程 | 抽检、返修、通过率统计，直接决定数据质量 |
| 一致性校验 | 多人标同一批数据的差异度（如 IoU 一致性、Kappa 系数） |
| 数据闭环 | 模型预测 → 预标注 → 人工修正 → 重新训练，形成飞轮 |
| 成本控制 | 标注是按量付费的，效率即成本 |

### 2.3 功能广度

- 只做 3D 框，没有语义分割、车道线、关键点、可行驶区域等任务类型。
- 半自动是传统 PCA 方法，没有接入深度学习预标注模型。
- 相机投影已实现（见 ⑥），但 radar 融合、多相机自动选帧尚未做。
- 时序是演示级：最近邻关联 + 线性插值（见 ⑧），生产需 Hungarian 匹配 + Kalman 预测 + 轨迹优化。
- 无后端、多人协作、质检流程（见第 2 节）。

## 3. 演进路线（按优先级）

如果你要把它往实用方向推进，建议这个顺序：

### 阶段 1：标注体验 ✅ 已完成
- ✅ 性能优化：体素下采样 + 距离 LOD + BufferGeometry 复用（⑧）
- ✅ 撤销/重做：命令模式 + 快照 + 连续操作合并（⑧）
- ✅ 轨迹插值：标首末帧，自动补全中间帧（⑧）
- 待做：拖拽控制点、多框批量操作、复制粘贴

### 阶段 2：多传感器与自动标注
- ✅ 相机投影叠加（⑥，已实现）
- ✅ 基础时序关联与插值（⑧，演示级）
- radar 融合、多相机自动选最佳视角（参考原仓库 `choose_best_camera_for_point`）
- 接入预标注模型（如 CenterPoint、PointPillars 的输出转成框）

### 阶段 3：工程化
- 后端（Node/Python）：数据入库、任务分发
- 用户系统与权限
- 标注结果版本管理

### 阶段 4：质量与闭环
- 质检工作流
- 一致性分析
- 对接训练管线，形成数据飞轮

## 4. 对照原仓库，继续学习

这个教学项目刻意做了简化。要深入理解工业实现，建议读原仓库源码：

| 想学什么 | 读哪个文件 |
|---|---|
| 自动标注算法 | `algos/rotation.py`, `algos/trajectory.py` |
| 鼠标画框交互 | `public/js/mouse.js`, `public/js/auto-adjust.js` |
| 框编辑逻辑 | `public/js/box_op.js`, `public/js/side_view_op.js` |
| 相机标定投影 | `public/js/calib.js`, `public/js/image.js` |
| 数据管理 | `public/js/data.js`, `scene_reader.py` |
| 保存逻辑 | `public/js/save.js` |

原仓库 96% 是 JavaScript，架构朴素但"干货"都在，非常适合对照学习——你现在已经有了数据模型和算法基础，再去读会顺畅很多。

## 5. 结业检验

问自己几个问题，能答上来就说明真的掌握了：

1. 一个 3D 框需要哪几个参数？8 角点是怎么算出来的？
2. 为什么自动拟合要先旋转到局部坐标系？
3. PCA 为什么能估计物体主方向？什么情况下会失效？
4. 为什么 BEV 用正交相机，3D 视图用透视相机？
5. 鼠标屏幕坐标怎么变成世界坐标？
6. 导出的 label JSON 里 `vertices` 和 `psr` 是什么关系？
7. 要支持相机图像投影，需要哪两个矩阵？

---

## 6. 最后

这个项目的价值不在于代码量，而在于它把"自动驾驶数据标注"这个领域拆成了你可以亲手触摸的几个核心概念。把它跑起来、改一改、坏掉再修好——这是最快的学习方式。
