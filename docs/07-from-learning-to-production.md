# ⑦ 从学习到生产

这个工具是一个精简的教学实现。这一篇只讲两件事：**它和工业级平台的差距在哪，以及沿着什么路径补**。

各模块已经实现的能力见 [README 功能清单](../README.md#2-能做什么功能清单)，这里不重复。

---

## 1. 与生产级工具的差距

按「系统 / 数据 / 质量 / 算法」四个维度看，本项目覆盖的是**单机标注闭环**，缺的是**组织级协作与数据治理**：

| 维度 | 生产级需要 | 本项目现状 |
|---|---|---|
| 存储 | PB 级原始数据放对象存储，元数据进关系库 | 单机 `public/data/`，几十 MB |
| 任务流转 | 任务切片、分派、回收，状态机驱动 | 无，一帧一帧手工打开 |
| 版本管理 | 标注多版本、回滚、审计日志 | 无，导出即覆盖 |
| 权限协作 | 标注员 / 质检员 / 管理员分权 | 无，单用户 |
| 质检流程 | 抽检、返修、通过率统计 | **指标有了**（IoU / kappa / 漏误标率），**流程没有** |
| 任务类型 | 3D 框 + 分割 + 车道线 + 关键点 + 可行驶区域 | 只有 3D 框 |
| 预标注 | CenterPoint / PointPillars 等模型产出候选框 | PCA 传统拟合，无深度学习 |
| 跟踪 | 马氏距离 + JPDA / 多假设 + 轨迹优化 | Kalman + Hungarian 已实现，但只用 2D 常速度 + 欧氏距离 |

一句话：**算法层追得上，系统层是从零开始**。这也是学习项目与工业项目最本质的差别——难点不在单点算法，在于让几百人并发标注还不乱。

## 2. 演进路线

如果要把这个项目往实用方向推，按下面的顺序做，每一步都能独立交付价值：

### 阶段 1：标注体验（大部分已完成）

- ✅ 性能：体素下采样 + 距离 LOD + BufferGeometry 复用（见 [第 ⑧ 篇](08-engineering-p0.md)）
- ✅ 撤销重做：命令接口 + 快照双栈 + 连续操作合并（同上）
- ✅ 轨迹插值：标首末帧自动补全中间帧（同上）
- 待做：拖拽控制点微调、多框批量操作、跨帧复制粘贴

### 阶段 2：多传感器与自动标注

- ✅ 相机投影叠加（见 [第 ⑥ 篇](06-calibration-and-projection.md)）
- radar / 多相机融合，按点云位置自动选最佳视角
- 接入预标注模型：把 CenterPoint / PointPillars 的输出直接转成待修正框，人工只做校正——这是标注效率提升最大的一步

### 阶段 3：工程化（从工具到系统）

- 后端：数据入库、任务切片与分发
- 用户系统与角色权限
- 标注结果版本管理 + 审计日志
- 并发控制：单机版已有快照栈经验，扩成多人时换成服务端的版本化快照（详见 [第 ⑨ 篇](09-interview-prep.md) 的并发方案）

### 阶段 4：质量与闭环

- 质检工作流：抽检 → 打回带原因码 → 返修 → 通过率统计
- 一致性分析：多人标同一批数据的差异度，用现有的 kappa / IoU 模块即可统计
- 对接训练管线：模型预测 → 预标注 → 人工修正 → 重训，形成数据飞轮

## 3. 对照原仓库继续读

本项目刻意做了简化。要理解工业实现，建议直接读 [SUSTechPOINTS](https://github.com/sustech-isus/SUSTechPOINTS) 源码：

| 想学什么 | 读哪个文件 |
|---|---|
| 自动标注算法 | `algos/rotation.py`, `algos/trajectory.py` |
| 鼠标画框交互 | `public/js/mouse.js`, `public/js/auto-adjust.js` |
| 框编辑逻辑 | `public/js/box_op.js`, `public/js/side_view_op.js` |
| 相机标定投影 | `public/js/calib.js`, `public/js/image.js` |
| 数据管理 | `public/js/data.js`, `scene_reader.py` |
| 保存逻辑 | `public/js/save.js` |

原仓库 96% 是 JavaScript，架构朴素但干货都在。你现在已经有了数据模型和算法基础，再去读会顺畅很多。
