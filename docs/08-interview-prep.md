# ⑧ 面试准备：系统设计题与项目话术

> 这篇不是技术文档，是**面试答题脚本**。
> 核心方法只有一句：**用「问题 → 设计选择 → 量化收益」讲每一件事**。
> 面试官不深挖某个算法的最优解，他看你能否在「标注效率—数据质量—工程成本」之间做权衡。

---

## 0. 先摆正这个项目的位置

一句话定位（开场就这么说）：

> "这是一个**学习导向的 3D 点云标注工具**，用 Vue3 + TS + Three.js 从零实现。
> 重点是把数据、几何、交互的本质吃透——PCD 解析、OBB 数学、自动拟合、相机投影、
> 撤销重做、多帧插值、百万点性能、质检度量。工业级的多人协作和后端调度我了解方案，
> 但没有生产实践。"

**为什么这样说加分**：诚实边界 + 知道边界在哪，比吹"我做了一个平台"经得起追问。
面试官要的是判断力，不是全知全能。

## 1. 系统设计题：「设计一个云端数据标注平台」

这是标注平台岗的高频题，也是区分"工具开发者"和"平台设计者"的分水岭。
**你不需要真写过后端，但必须能白板讲清四层**。下面按答题顺序组织。

### 第一层：任务状态机（先讲这个，因为它定义了系统边界）

一句话破题：
> "标注平台本质是一个**任务流转系统**，先把状态机定清楚，其它模块都围绕状态变化工作。"

状态链路（口述时画在白板上）：

```
创建 → 分配 → 标注中 → 提交质检 → 质检中 ─┬→ 通过 → 完成
                                          └→ 打回 → 标注中
```

关键设计点（每个都要说出"为什么"）：
- **状态存在服务端**，不存浏览器——否则刷新就丢、多人会冲突。
- **每次状态流转必须有审计日志**——谁在什么时间把哪帧从"标注中"改成"提交质检"，
  这是后面质量追溯和责任划分的基础。
- **打回要带原因码**（漏标/框偏/类别错），不能直接退回"标注中"——
  否则标注员不知道改什么，来回拉锯。

### 第二层：多人协作与冲突处理（面试官最爱追问）

破题句：
> "同一帧被两个人同时打开，核心是**并发控制**。有三种方案，我按场景选："

| 方案 | 做法 | 适用 |
|---|---|---|
| 悲观锁 | 打开即加锁，别人只读 | 质检复核等互斥场景 |
| 乐观锁 | 提交时带版本号，版本冲突则拒绝并提示 | 标注主流程（冲突少，吞吐高） |
| 操作转换 OT / CRDT | 合并两人的编辑 | 实时协同编辑，复杂度最高 |

**锚定你的项目**（这是最关键的一句）：
> "我做的单机版用快照栈实现了撤销重做。扩成多人时，思路是把本地 history 栈
> 换成服务端的**版本化快照**：每次提交携带 baseVersion，服务端比对，
> 冲突时把两人的差异都展示给仲裁人。我在项目里已经验证了快照深拷贝和分支处理，
> 这些经验能直接迁移。"

——用你写过的东西当锚点，比背"乐观锁定义"强十倍。**面试官能看出你是真做过的**。

### 第三层：存储与数据治理（体现规模感）

破题句：
> "自动驾驶数据是 **PB 级多模态**，存储要分两类：热数据和冷数据。"

- **对象存储**（S3/MinIO）存原始图像、点云、视频——大文件、一次写入多次读取。
- **元数据 + 关系库**存任务状态、标注 JSON、版本号——结构化、高频查询。
- **数据集版本化**（DVC/MLflow）：每次标注变更可追溯、可复现，
  否则模型效果波动时你无法定位是哪批 GT 出了问题。
- **Schema 设计**：GT 结果要能被感知/规控模型直接消费，
  所以格式不能随便定——这正是我在项目里**复刻 SUSTechPOINTS label JSON**
  而不是自造格式的原因。

### 第四层：调度与弹性伸缩（收尾，体现工程完整度）

- **任务队列**（Celery + Redis）：把"预标注推理""格式转换""质检统计"做成异步任务，
  避免 HTTP 请求里跑几十秒的模型。
- **GPU Worker 按积压量自动扩缩**（K8s HPA）：夜间无人标注时把 GPU 缩到 0，
  白天预标注高峰自动扩容——这是成本控制，不是纯技术炫技。
- **主动学习闭环**：模型对未标注数据打分 → 挑困难样本（不确定性高 / 长尾类别）
  → 进入标注队列 → 标注完触发重训。这是数据飞轮，也是这个岗位的价值上限。

### 收尾金句

> "所以我的设计思路是：**状态机定边界、乐观锁保并发、对象存储扛规模、
> 任务队列做异步、主动学习提效率**——每一层都是为了解决具体的效率或质量问题，
> 不是为了堆技术名词。"

## 2. 逐项项目话术（按"问题→选择→收益"重写）

下面每一项都是**面试官追问时你的标准回答结构**。三句话，不超过 30 秒。

### ① 为什么用 PCA 而不是深度学习做自动拟合？

- **问题**：教学项目要零外部依赖、可解释、能跑在任何机器上。
- **选择**：用 PCA 估主方向 + 局部坐标 min/max 拟合框。
- **收益**：20ms 内完成、纯数学可讲清原理；**代价**是密集相邻目标、非凸形状会失效——
  生产环境我会接 CenterPoint/PointPillars 做预标注，PCA 只作 fallback。

### ② UNDO 怎么实现？为什么选快照不选差量命令？

- **问题**：画框、删除、快捷键、属性面板都要能撤销，不能有的能有的不能。
- **选择**：所有编辑统一走 `state/studioCore.ts` 的 `mutate()` 入口 + `Box3D[]` 完整快照双栈。
- **收益**：实现简单、状态一定一致。三个工程细节我处理了：
  新操作清空重做栈（分支）、连续滑杆拖动合并为一条历史、快照必须深拷贝。
  **代价**是内存占用随框数线性增长——但一帧几百个框完全可接受，
  真要优化再上差量命令（Command 模式记录 inverse 操作）。

### ③ 跨帧 ID 怎么保持？

- **问题**：同一个车在连续帧里必须是同一个 obj_id，否则跟踪训练数据全废。
- **选择**：教学版用最近邻 + 角度最短弧插值；生产级版用 **Kalman 预测 → 门控 → Hungarian 全局分配**（两者都实现了）。
- **收益**：先在白板上讲**交叉案例**——两车相向换位，纯距离贪心给出"总距离 0"的完美匹配，却把两个 ID 全串了；Kalman 用速度预测出正确位置、Hungarian 给出同样距离 0 但 ID 正确的配对。演示序列补出 9 个框、obj_id 一致。
- **诚实边界**：当前是 2D 常速度 + 欧氏距离；生产用马氏距离（考虑协方差）+ JPDA/多假设跟踪处理遮挡。

### ④ 百万点怎么不卡？

- **问题**：直接把 100 万点塞进 BufferGeometry 会卡死。
- **选择**：体素网格下采样（0.5m）+ 距离 LOD（近处全留、远处抽稀）+ 引用比较避免重复上传 GPU。
- **收益**：**实测数字**——100 万 → 体素 50 万（1.35s）→ LOD 27 万（36ms），
  3.7× 压缩，内存 11.4MB → 3.1MB。数字是跑出来的，不是 Estimates。
  **延伸**：更大规模要做分块加载 + Worker 里解析，避免主线程阻塞。

### ⑤ 怎么保证标注质量？

- **问题**：能标不等于标得准，必须有量化指标。
- **选择**：BEV 旋转矩形精确 IoU + 高度重叠比近似 3D IoU，贪心匹配两版标注，
  算漏标/误标率、F1、Cohen's kappa、中心与朝向误差。
- **收益**：演示数据能直接跑出 kappa=0.57、mIoU=0.74 这样的报告，
  一眼看出哪类目标标得差。**诚实边界**：精确 3D OBB 相交要 SAT，
  匹配生产用 Hungarian——我的近似在质检场景够用且快一个量级。

### ⑥ 为什么复刻原仓库的 JSON 格式？

- **问题**：自造格式看起来自由，但导出的标注进不了训练管线。
- **选择**：逐字段复刻 `psr / obj_type / obj_id / vertices`，连 8 角点顺序都对齐。
- **收益**：导出文件能直接被 SUSTechPOINTS 读取——这体现的是**对接上下游的工程意识**，
  不是"能存盘就行"。

## 3. 其他可能被问到的（速查）

上一节六条是主答，下面是容易被顺带追问、但不必展开的：

| 追问 | 你的底子 | 一句话回答要点 |
|---|---|---|
| 行主序 / 列主序坑 | ✅ 踩过 | 原仓库 `extrinsic[3]/[7]/[11]` 取平移 → 行主序，照搬 Three.js 列主序会全错位 |
| 两人同时标一帧 | ⚠️ 知方案 | 乐观锁 + 版本化快照，锚定本地快照栈经验 |
| 深度学习预标注 | ⚠️ 知概念 | 知道 CenterPoint / SAM2 / VLM 的范式，本项目用 PCA 教学版 |
| Python / Spark / MLOps | ❌ 非本岗 | 那是算法与数据平台赛道，投前端向标注平台岗不深挖 |
| CVAT / Label Studio | ❌ 半小时科普 | CVAT 专精 CV 且原生支持 3D 点云；Label Studio 强在多模态 + ML Backend |
