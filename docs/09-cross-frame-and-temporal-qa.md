# ⑨ 4D 进阶：跨帧编辑与时序质检

> 上一篇做了轨迹叠加回放，把 4D 数据"看"了出来。这一篇做两件事：
> 让编辑能"跨帧传播"（改一帧带出一条轨迹），让质检能"跨帧检查"（发现单帧看不出的错误）。
> 这两块正是成熟标注平台"4D 工具 / 智能审核"卖点的核心组成。

---

## 一、跨帧编辑：改一帧，带一条轨迹

### 问题的起点：改了一帧的框，其他帧怎么办？

真实标注不可能逐帧手改——一辆车连续 50 帧，改 50 次效率极低。所以必须支持**把当前帧的修改传播到其他帧**。关键是要区分两种意图：

| 策略 | 做法 | 适用场景 |
|---|---|---|
| **整框替换** `replace` | 用当前框原样覆盖其他帧的同 id 框 | "这个目标从头到尾尺寸/朝向就该是这样"，但会抹掉各帧位置差异 |
| **增量平移** `offset` | 算出当前框相对"编辑前"的位移/朝向变化量，叠加到其他帧 | "整体标偏了 2 米"的修正，保留各帧自己的位置和轨迹形状 |

还有第三个维度是**范围**：`forward`（后续帧）/ `backward`（前序帧）/ `all`（全部帧）。

### 核心实现：`sequence.ts` 的 `propagateBox`

```ts
export function propagateBox(
  frames, currentFrame, boxId,
  referenceBox,  // 编辑前的快照
  editedBox,     // 编辑后的框
  scope, strategy,
): number {
  // offset 策略：先算增量（朝向走最短弧，避免 ±π 绕圈）
  const dx = edited.position.x - reference.position.x
  const dyaw = lerpAngle(reference.yaw, edited.yaw, 1) - reference.yaw
  // 遍历符合范围的帧，找同 id 框：
  //   replace → 整框替换；offset → 在原位置叠加增量
}
```

**一个容易忽略的细节**：App 层要在选中框时保存一份 `selectedBoxOrigin` 快照。因为用户编辑后，
原始值就没了——没有"编辑前"，`offset` 策略无从算起。这是"增量传播"能成立的前提。

UI 入口在属性面板底部：选中框 → 选范围与策略 → 点「⇢ 应用到其他帧」。

## 二、时序质检：把"时间维度的一致性"变成指标

### 为什么单帧质检不够

`quality.ts` 检查的是"一帧里标得准不准"。但一个框可以每帧都贴得很准，整体却是错的：

- 每帧都把 A 车标成 B 车的 id → 单帧看不出，连成轨迹才发现 ID 串了
- 逐帧独立标注没做平滑 → 轨迹抖成锯齿
- 目标在中间帧漏标 → 首末帧都在，中间突然消失

这些只有把时间轴拉开才暴露。这正是 MolarData 等平台"智能审核"的能力。

### 四类检测（`core/temporalQA.ts`）

`evaluateTemporal(frames, opts)` 返回时序报告，逐条轨迹检查：

| 类型 | 判据 | 严重度 |
|---|---|---|
| **ID 跳变** `id_switch` | 相邻帧位移 > 阈值（默认 12m）→ 疑似把两个目标的 id 串了 | error |
| **速度突变** `speed_jump` | 相邻两段速度差 > 8 m/s → 中间帧标错位置或漏标 | warn |
| **轨迹抖动** `jitter` | 连续两段运动方向反转角 > 2 rad → 手抖/没做平滑 | warn |
| **轨迹断裂** `track_gap` | 目标首末帧都有、中间帧缺失 → 漏标（遮挡应显式标 visibility） | warn |

报告含 `counts` 分类统计、`score` 健康分（error 扣 15、warn 扣 6，下限 0），
UI 里每条问题可点击跳到对应帧。

**已知边界**：这里用固定阈值 + 相邻帧统计。生产系统会把阈值按目标类别/距离自适应，
并用 **Kalman 残差**（观测 vs 预测位置偏差）代替裸位移——预测残差对"匀速目标突然跳"更敏感，
也能自然处理加减速场景。

### 演示：缺陷注入

`injectTemporalDefects(frames)` 在干净序列上故意注入四类问题（固定种子可复现），
配合 UI 的「⚠ 演示缺陷注入」按钮，一键看到报告从健康分 100 掉下来、四类问题各被检出几处。

**一个教学上的坑**：演示序列 `generateDemoSequence` 故意让后 3 个目标只标首末帧（稀疏标注），
质检会正确报出 9 处 `track_gap`。这不是 bug——所以演示时应先点「轨迹插值补全」把稀疏帧补上，
再做质检，报告才干净。这个"先补全、后质检"的顺序本身就是真实工作流。

## 三、设计取舍

**跨帧编辑的难点是"意图识别"，不是代码量。**`propagateBox` 本身只是遍历帧、改字段，真正要想清楚的是：用户说"改这个框"，是想让整条轨迹都变成这样，还是只修正当前帧的偏差？于是拆成 `replace` 与 `offset` 两种策略，前者抹平各帧差异，后者保留轨迹形状只做平移。而 `offset` 必须在选中时保存编辑前快照才能算增量——这也解释了为什么 `studioCore` 里要留一个 `origin` 容器，专门存"选中那一瞬间的框"。

**时序质检的难点是把"时间一致性"变成可计算的指标。**直观感受是"这辆车跳了一下"，要落成代码就得选判据：用相邻帧位移查 ID 跳变、用速度差查瞬移、用方向反转角查抖动、用首末帧存在但中间缺失查断裂。四类判据都用相邻帧统计，而不是全局拟合——代价是阈值必须拍死（12m / 8 m/s / 2 rad），好处是每个告警都能定位到具体帧和具体判据，人能复核。

**为什么不直接上跟踪器。**质检只回答"这条轨迹看起来可疑吗"，不需要最优关联；用 Kalman 残差做判据会得到更敏感的结果，但也意味着质检结果依赖跟踪器调参，出问题难定位。现在这样，质检和关联演示是两条独立链路，各自可测。
